# Target system — decisions and deviations

The quality-infrastructure initiative (schemas, validation, rules, benchmarks, evidence-aware scoring, freshness, review history, CI, tests) was scoped with explicit room to "adapt names or implementation when the current repo structure suggests a better alternative" — with the requirement that any real deviation be documented here, not silently made. This is that record.

## Decisions and their alternatives

| Area | Decision | Alternative considered | Why not the alternative |
|---|---|---|---|
| Personal profile location | Keep `packs/personal/<name>/` | A parallel `profiles/{default,personal,templates}/` tree | `doctor.sh`, `update.sh`, `uninstall.sh` already preserve and validate this path generically (glob `packs/personal/*`, never a hardcoded name). Moving it means rewriting three working scripts to fragment "packs" as a concept, for zero functional gain. |
| YAML parsing | Hand-rolled ~350-line stdlib parser (`schemas/yaml_subset.py`) | PyYAML or ruamel.yaml | `python3` is already the repo's one accepted dependency (via `doctor.sh`'s `json.tool` call). A pip package turns "clone and run" into "clone, pip install, run" — for files simple enough (flat key:value, one-to-two levels of nesting, inline flow lists) that a stdlib parser handles the entire real corpus correctly, verified against all 48 pre-existing `metadata.yaml` files plus synthetic rule-registry-shaped content. |
| Metadata migration | Pure text-append, never rewrite existing lines | A round-trip-preserving rewrite (needs ruamel.yaml) | The migration only ever *adds* new top-level keys at EOF; it never edits an existing line, so there is nothing to "preserve" that a naive append doesn't already preserve byte-for-byte. |
| Required vs. optional schema fields | Required = only the 7 fields already universal across every existing pack | Requiring the full extended field set immediately | Makes the schema non-breaking *by construction*: `akos validate packs` reports zero errors against the pre-existing corpus from the day it ships, with no migration gate in front of it. |
| Rules registry | Filesystem-as-registry: `rules/<domain>/<id>.yaml` + sibling `.py`, discovered by glob | A single hand-maintained `rules/registry.yaml` index | Mirrors how `packs/` is already discovered. A hand-maintained index recreates the exact drift risk `doctor.sh`'s pack-routing-table anti-drift guard exists to catch — a rule could be added and forgotten in the index, silently invisible to the runner. |
| `A11Y_INPUT_NO_LABEL` | Shipped as Level B (heuristic), capped at MEDIUM, excluded from CRITICAL-only exit gating | Ship as Level A (deterministic, CI-gating) | Real HTML/JSX label association is a tree-structural relationship (wrapping `<label>`, form-library context, spread props) a regex cannot resolve. Gating CI on it would produce the highest false-positive rate of the eight rules and would undermine trust in the other seven by association. |
| `MISSING_ROLLBACK_MIGRATION` | Split into two rules: `MIGRATION_NO_DOWN_FILE` and `DESTRUCTIVE_MIGRATION_NO_GUARD` | One combined detector | Different applicability logic (Supabase's default forward-only migrations make "flag every migration lacking a down file" 100% false positives on a project that never adopted the convention) and different false-positive profiles. One detector doing both needs an internal config system to avoid over-firing on the common case. |
| Benchmark runner | Single `benchmarks/runners/run.py` (Python), thin bash wrapper in `bin/akos` | A bash-orchestrated runner calling out to per-case shell scripts | Same split `doctor.sh` already uses: bash for CLI/orchestration, Python stdlib the moment real recall/precision arithmetic and structural diffing are involved. |
| Level C (LLM-assisted) evals | Mock provider required (deterministic, no network, the only one CI ever uses); an optional local-only passthrough to `claude`/`codex` CLI is documented, not wired by default | A real hosted LLM API integration | Satisfies "provider-agnostic, offline-capable" without inventing API-key plumbing or a second costed dependency for the one part of the system every acceptance criterion says is optional. A local CLI passthrough reuses a tool already on this machine's PATH rather than requiring new credentials. |
| Review history location | `.akos/reviews/` in the **consuming project**, not this repo | Storing review history inside the AKOS repo itself | Matches `.akos/config.md`'s existing locality — it's project-local state. Reviews are LLM-driven, not script-driven, so `akos history record` is a bridge the `akos-review` skill's final step calls, not something a script produces on its own. |
| Exit codes | New commands (`validate`, `rules`, `benchmark`, `freshness`) get a documented 0/1/2 scheme (see `docs/cli/exit-codes.md`); the 10 pre-existing commands keep their exact current 0/1 behavior | Unifying all commands under one exit-code convention | Changing an existing command's exit code could silently break anything already scripted against it. Additive, not unifying. |

## What did *not* change

- The 17-file pack contract, the 13 agent files' prose bodies, the 9 workflows, the 45+ knowledge packs' content, the reasoning-profile weight tables, the review pipeline's severity/decision semantics, the personal layer's authority (Level 0, below the safety floor) — none of this initiative touches knowledge content, only the verification layer around it.
- `bin/akos`'s 10 pre-existing commands' behavior and exit codes.
- `write_marked_section`'s external contract (still called the same way by every caller) — only its internal implementation changed, to fix the BSD-awk multi-line bug found in M4.

See `docs/architecture/current-system.md` for the pre-existing baseline this builds on, and `docs/migration/v1.1-to-next.md` for the version-by-version summary of what shipped.
