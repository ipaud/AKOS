# v1.11.1 and v1.12.0 remediation evidence

This document records the local acceptance evidence for the remediation that
followed the 2026-07-23 full AKOS review. It is not a release record: no tag,
push, GitHub release, or remote publication was performed.

## TDD trace

Regression tests were added before each implementation and observed failing
against the vulnerable behavior. The RED cases included:

- review roots, review entries, internal review files, `.gitignore`, and
  managed install targets replaced by symlinks or swapped during an operation;
- corrupt or unexpected history entries allowing a partial `clean`;
- detector reads swallowing `OSError`, malformed detector output, scan-budget
  overflow, and suppressions applied to non-suppressible findings;
- out-of-order SQL migrations, quoted and schema-qualified identifiers,
  policy lifecycle changes, dynamic SQL, and a final statement without `;`;
- missing secret formats, detector/redactor drift, and service-role client-path
  false positives and false negatives;
- CI self-scan exit-code/JSON inconsistencies, CLI usage-code drift, and E2E
  fixtures escaping their owned temporary checkout;
- accessibility comments/empty labels, provisional mobile evidence, Review
  Summary mobile weighting, routing, and strict monetary parsing.

Each case was then driven to GREEN with the smallest compatible change. The
public JSON shapes and the existing CLI success/finding exit-code contracts
remain stable.

## Final local gates

The final working tree produced:

- unit tests: **454/454 passed**;
- rule benchmarks: **30/30 passed**;
- integration scripts: **12/12 passed**;
- Python branch coverage: **83.8%** (threshold: 80%);
- strict schema validation: **76 files clean**;
- rules self-scan: **8/8 rules executed**, 36 expected fixture findings,
  zero execution errors, and zero blocking findings outside the exact
  allowlisted `rule_id` + fixture-case pairs; secret findings have no
  exception;
- `doctor.sh`: **65 passed, 2 release-state warnings, 0 failed**;
- Bash syntax, ShellCheck at warning severity, Python compilation, routing,
  freshness, and `git diff --check`: passed.

The two doctor warnings are expected until release authorization: the working
tree contains unreleased source changes and no `v1.12.0` tag exists.

The final independent security/integrity re-audit reproduced the previously
blocking PoCs and returned **PASS with 0 CRITICAL and 0 HIGH findings**. In
particular, the self-scan allowlist is limited to four exact
`SUPABASE_RLS_DISABLED` evidence paths; `SECRET_IN_SOURCE` has no exception.

## Remaining release boundary

GitHub Actions, including the Ubuntu/Python 3.10 and macOS/current-Python
matrix, must pass remotely before publication. Publishing, pushing tags, or
creating a release requires separate explicit authorization.

`schemas/history.py` and `bin/marked_sections.py` temporarily exceed the normal
file-size guideline because the fd-relative, no-follow, rollback-safe
filesystem implementation is security-sensitive. Extracting that code is
deferred as non-blocking maintainability work rather than reopening the hotfix
with a structural rewrite.
