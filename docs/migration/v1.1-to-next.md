# Migrating from v1.1–1.3 to v1.4

**Nothing breaks.** Every change in this range is additive — no existing command's behavior or exit code changed, no pack content changed, no `.akos/config.md` field was removed, `packs/personal/pau-avila/` keeps working with zero action required. This document is "here's new stuff you can opt into," not a breaking-change guide, because there isn't one.

## If you're already using AKOS (v1.1–1.3), do you need to do anything?

**No.** Pull the update, run `./doctor.sh` once to confirm (it now reports two new advisory sections — Schema validation and Pack freshness — both informational, neither breaks a previously-green run). That's it.

## What's new, if you want it

### Formal contracts (v1.4)
`akos validate [packs|agents|workflows]` checks pack `metadata.yaml`, agent frontmatter, and workflow frontmatter against JSON Schema. Every pre-existing pack validates clean immediately — the schema's required fields are exactly the 7 fields already universal. New optional fields (`id`, `status`, `last_reviewed`, `review_after`, `maintainer`, `license`, `deprecated`) were backfilled into all pre-existing packs by a one-time, already-run migration (`bin/migrate-pack-metadata.py`) — nothing for you to run again. See `docs/contracts/knowledge-pack.md`.

### Executable rules (v1.4)
`akos rules run <your-project-dir>` runs 8 deterministic/heuristic checks (RLS-disabled tables, overly-permissive Supabase policies, likely secrets, `service_role` reachable from client code, unlabeled inputs, missing migration rollback files, unguarded destructive SQL) against a real codebase — this is genuinely new capability, not a reformulation of anything AKOS did before. See `rules/README.md`, `docs/rules/authoring-rules.md`.

### Benchmarks (v1.4)
`akos benchmark run` — a regression suite for the rules above. Only relevant if you're extending or modifying `rules/`; otherwise nothing to do. See `docs/benchmarks/overview.md`.

### Personal profiles, decoupled (v1.4)
`.akos/config.md` gained a `## Personal profile` section (`personal_profile: pau-avila`). **Absent means `pau-avila`, exactly as before this field existed** — every project's existing `.akos/config.md` keeps working with zero edits. Want your own profile instead of the shipped default? `akos profile create <name>` then `akos profile use <name>`. See `docs/profiles/personal-profiles.md`.

### Evidence-aware scoring (v1.4)
The Review Summary template gained a `## Coverage` section and per-finding confidence tags. This changes what a *future* review's output looks like — nothing about *past* reviews or the decision logic (PASS/PASS WITH FIXES/BLOCKED) changed. See `docs/scoring/evidence-confidence-coverage.md`.

### Freshness (v1.4)
`akos freshness` reports which packs are due for a re-read against their sources. Entirely new, informational, never gates anything unless you pass `--fail-on`.

### Review history (v1.4)
`akos-review`'s skill instructions now record every review to `.akos/reviews/` in your project (via `akos history record`), so `akos history compare <a> <b>` can show score/decision deltas across runs. Opt out per-review by telling the agent it's a throwaway check.

### CI templates (v1.4)
`.github/workflows/{ci,benchmarks,freshness}.yml` are AKOS's *own* CI, for anyone forking/contributing to AKOS itself — not something that runs against your consuming project. If you want similar checks (`akos validate`, `akos rules run`, `akos freshness`) in your own project's CI, copy the relevant steps.

## Version history in this range

- **v1.1.0** — AKOS became invocable as a Claude Code / Codex CLI skill (`skills/akos`, `skills/akos-review`), plus plugin manifests for both marketplaces.
- **v1.2.0** — `content/` domain (ux-writing, gov-uk-content-design); `copy-reviewer` was one of the twelve pipeline lenses with no domain of its own until this.
- **v1.3.0** — `mobile/` domain (responsive-web, touch-ergonomics); `scoring/mobile-score.md`; `content/gov-uk-content-design` made conditional (validated against a real screen — fired on 1 of 19 findings on a control-dense surface, `ux-writing` covering the rest).
- **v1.4.0** (this range) — the quality-infrastructure initiative documented here: contracts, validation, executable rules, benchmarks, evidence-aware scoring, freshness, review history, personal-profile decoupling, CI, and tests. See `CHANGELOG.md` for the full per-commit detail.
