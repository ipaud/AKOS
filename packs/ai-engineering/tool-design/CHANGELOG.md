# Changelog — tool-design

## [1.1.0] — 2026-07-20

### Fixed

- `examples.md` graded `history clean`'s missing dry-run as "a soft finding rather than a defect", granting it the TDE51 exemption for commands whose scope is fixed by their arguments. The exemption did not hold: `--keep` defaulted to 20, so the command's real scope was however many reviews existed past 20 — unseen state, which is the ★ safety-floor CRITICAL row. Found by applying this pack's own checklist to the same code and reaching BLOCKED where the example reached "well above the midpoint". A worked example that under-applies its own rules teaches under-application.

## [1.0.0] — 2026-07-20

### Added

- First complete version: all 17 schema files populated with operational content.
- Principles TD1–TD16, each with an operational corollary, covering the human-tool-is-not-an-agent-tool claim, name and description as the entire interface, small composable tools over a monolith, one call and one coherent effect, typed and schema-validated inputs over free-text conventions, responses that return evidence rather than acknowledgement, errors that state the next action, repeat-safety declared at the tool's own boundary, previews for consequential operations and confirmations for destructive ones, result sets bounded by the tool rather than by caller restraint, stable references returned for the next call, read-before-write enforced in the surface rather than hoped for, the tool/resource/prompt primitive split, description iteration against observed agent calls, the tool surface as a competing set, and the testable contract.
- Engineering rules TDE1–TDE86, grouped into naming and description, granularity and composition, input design, output and evidence, errors, repeat-safety, consequential and destructive operations, bounded results, stable references, read-before-write in the surface, primitive separation, iteration and evaluation, and surface hygiene.
- The three-primitive table — tool (an operation with an effect), resource (readable material, free to call), prompt (a reusable parameterized template) — distinguished by the one property that most affects an agent deciding whether to call something: whether calling is free (`mental-models.md`, `decision-framework.md`).
- The composition ladder as a decision tool: the target granularity is the coarsest at which every failure is still attributable to one effect the caller can act on, with the half-success test for "too coarse" and the invariant-ritual test for "too fine."
- The ambiguity tax and the evidence gap as named diagnostic models — the first reframing tool quality from error rate to the count of calls that exist only because something was unclear, the second measuring what a caller can legitimately assert after reading only a response.
- Anti-patterns derived from the pack's own principles: the tool that does too much, the acknowledgement response, the blind destructive call, the unbounded return, the silent non-idempotent retry target, the stringly-typed parameter, the uninformative error, the positional reference, the overloaded mode parameter, the collapsed primitive, the never-revised description, the catalogue surface, the endpoint transliteration, and the untestable contract.
- Review checklist and scoring rubric that treat an unrecoverable partial effect, a destructive operation reachable without preview or confirmation, and a write returning no evidence as correctness defects, with a hard cap at 59 for any open CRITICAL, a cap at 69 where observed wrong calls are corrected in the caller's prompt rather than at the interface, and a cap at 79 where the surface has never been exercised by a real agent with the traces read.
- Sources cited: Anthropic's "Writing Effective Tools for AI Agents" and the Model Context Protocol Specification (Level 2, published engineering practice and specification), plus SWE-agent (Yang et al.) for the agent-computer-interface argument. The pack is organized around the AKOS 17-file contract rather than any source's structure.
- A tool-definition worksheet and a set-level surface audit as injectable prompt fragments, alongside the standard build-mode constraint block, review lens, and tight-budget one-liner.
- A self-referential audit, in `examples.md`: this repository's own `bin/akos` subcommands and `rules/runner.py` read against this pack's checklist. Credited for verb-object subcommand naming, three separate errors that name the tool satisfying the prerequisite (`profile use`, `profile show`, `rules explain`), an error enumerating valid values (`review`), three distinguishable write outcomes from `write_marked_section`, guarded and idempotent creates, and `rules/runner.py`'s `Finding` shape — `rule_id`/`severity`/`evidence[{path,line_start}]`/`recommendation` plus three distinct exit codes — as a well-formed structured tool result. Faulted for `link-project` as a pure alias of `install-project` (TDE2), `install-project` performing four independent writes behind one name with no per-file report (TDE12, TDE16), no structured output from any bash-native subcommand while the Python-backed ones offer `--format json`, no marking of which subcommands mutate (TDE4), `history clean` advertised with no statement of scope or reversibility, `profile use` writing without a version check, `show-profile` branching on arity and duplicating `profile list` from a hardcoded literal, and no result bounds anywhere — bounded today by scale rather than by design (TDE58).
- Scope boundary recorded against `packs/ai-engineering/agent-security` (injection via tool output, poisoned tool descriptions, excessive permissions, consent and audit, and MCP's trust-boundary and authorization concerns — all deliberately out of scope here), `packs/ai-engineering/agent-foundations` (which architecture calls the tool), and `packs/ai-engineering/context-engineering` (what the agent can see).
- Cross-links recorded to `core/authority-model.md` and `core/decision-framework.md` (the general patterns this pack specializes), `core/source-policy.md` (its own distillation discipline), `core/scoring-model.md` (scoring bands), `bin/akos` and `rules/runner.py` (the audited in-repo artifacts), and to the `backend/rest` and `architecture/design-patterns` packs — REST in particular as the older home of the pagination, idempotency, and status-semantics concerns this pack restates for a caller that cannot read documentation. TD8 is recorded as the tool-side counterpart to agent-foundations' AF16, and TD10 as the tool-side origin of context-engineering's CE1/CE6 failure.
