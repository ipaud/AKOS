# Glossary — Agent Security Pack

- **Actuator boundary** — the point in an architecture where a generated token becomes an effect in the world: a tool call, a credential use, a write, a send. Every control in this pack sits on that line or beyond it; anything upstream is a mitigation.
- **Agentic AI** — a system in which a language model plans, selects tools, and takes actions with real effects, rather than only producing text for a human to act on. The autonomy is what creates the attack surface this pack covers.
- **Allowlist** — an explicit set of permitted destinations, commands, paths, or operations, with everything else denied by default. The only posture that stays correct as attack variants change; the counterpart to a blocklist, which enumerates the defender's imagination.
- **Blast radius** — the union of what an agent's credentials, tools, filesystem access, and network reach permit. A successful injection transfers this whole envelope to whoever authored the text the agent read, which makes it the honest measure of an agent's risk.
- **Confused deputy** — a privileged component induced to act for an unprivileged requester, because it answered "am I allowed to do this?" instead of "is the asker allowed to have this done?" Invisible in logs, since nothing is bypassed and every check passes.
- **Control** — a defense enforced by a component the attacker's text cannot address: a scoped credential, a sandbox, an egress proxy, an approval gate. Bounds what happens when an attack succeeds. Contrast mitigation.
- **Direct prompt injection** — a user instructing an agent to disregard its constraints. Bounded by what that user was already permitted to do, and the less dangerous of the two forms.
- **Egress path** — any route by which bytes in an agent's context become bytes someone else observes: an outbound request, a rendered image or iframe, a DNS lookup, a public comment, a webhook, a commit message, a filename, an error string, a log sink.
- **Excessive agency** — an agent holding more autonomy, permission, or capability than its task requires. Not a vulnerability on its own; the multiplier that turns a successful injection into an incident.
- **Exfiltration triangle** — the three ingredients a leak needs in one run: sensitive data in context, untrusted content in context, and a reachable egress path. Any two are survivable; all three is a live vulnerability, and the third is the one teams most often fail to classify.
- **Human-approval bypass** — any route to a gated action that skips the gate: a second tool exposing the same capability, a batch endpoint, a sub-agent, or a lower-level API the agent also holds. A gate covering one route covers none.
- **Idempotent** — see [agent-foundations](../agent-foundations/glossary.md); relevant here because a duplicated side effect and an unauthorized one need the same guard at the same boundary.
- **Indirect prompt injection** — an instruction embedded in content the agent reads — a document, web page, email, file, or tool result — that the agent then obeys. The dangerous form, because nobody with legitimate access typed it and the operator's own trust is the delivery mechanism.
- **Insecure output handling** — treating an agent's output as safe to execute, render, query, or path-resolve without the validation the same bytes would get from an anonymous internet user.
- **MCP (Model Context Protocol)** — an open protocol for connecting agents to external tools, resources, and prompts through servers. Each server is simultaneously third-party code, third-party credentials, and third-party prompt content, which is why an agent's server list is a supply chain.
- **Memory poisoning** — writing a false fact into an agent's persistent memory so it is trusted and acted on in later sessions. The highest-leverage form of injection, because it escapes the containment of a single run.
- **Mitigation** — a defense that reduces how often an attack succeeds but is adjudicated by the component under attack: instructional hardening, delimiters, injection classifiers. Worth having; never a bound. Contrast control.
- **Principal** — the identity on whose behalf an action is taken. A user or a service is a principal; a document is not, and content asserting an identity is content.
- **Provenance class** — the trust label attached to a piece of context by the channel it arrived through: system, operator, user, or untrusted. Assigned at the transport boundary, checked at the actuator, and never inferred from what the content says about itself.
- **Provenance ladder** — the ordering of those four classes, in which a lower class may restrict what a higher one permitted but may never widen it. Descent only.
- **Rug pull** — a tool, server, or package that is benign when reviewed and hostile after an update. Distinctive in agent systems because part of the payload is natural language aimed at the model's judgment rather than code aimed at a runtime.
- **Sandbox** — an execution environment with an explicit filesystem root, an explicit egress allowlist, no ambient host credentials, and resource limits. The canonical control: it works whether or not the model was fooled.
- **Sleeper fact** — a poisoned memory record with a long dwell time, read in later sessions by different principals with no trace of its origin, and corroborated by reasoning that derives from it.
- **Tool poisoning** — a malicious or compromised tool description, or a hostile payload disguised as ordinary tool output. Effective because tool names, descriptions, and parameter docs are prompt content and are read by the model as guidance.
- **Trust class** — see provenance class.
- **Untrusted content** — anything the agent reads that did not arrive through a genuine instruction channel: retrieved documents, web pages, file contents, database rows, email bodies, and tool results. The default classification, including for systems you own, because ownership of the system is not ownership of what was written into it.
