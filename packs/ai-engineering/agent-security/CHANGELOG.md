# Changelog — agent-security

## [1.0.1] — 2026-07-26

### Changed

- **Promoted from `draft` to `stable`.** Assessed against the draft→stable criterion
  now recorded in [core/knowledge-schema.md](../../../core/knowledge-schema.md): no
  placeholder content in any required file, every cited rule code defined in this pack,
  every `metadata.yaml` source grounded verbatim in `references.md`, the `ASE`
  prefix owned by this pack alone, and the independent-distillation line present in
  `README.md`. The first four are verified by the existing unit suite; the last by a new
  `doctor.sh` check added alongside this promotion. `last_reviewed` re-stamped to the
  promotion date and `review_after` recomputed from the Level 1 545-day cadence.
- **Now routable automatically.** The pack's row moves from the Experimental table into
  the stable routing table in `skills/akos/SKILL.md`, so it enters the "2-5 packs closest
  to the task" selection instead of loading only when a user names it, and stable agents
  may now depend on it.

## [1.0.0] — 2026-07-20

### Added

- First complete version: all 17 schema files populated with operational content. Authority level 1 (standards bodies — OWASP GenAI Security Project, NIST, and the Model Context Protocol specification), placing the pack on the safety floor `core/constitution.md` Article 2 never waives; `review_after` set on the 545-day Level 1 cadence rather than the scaffold's 270-day default.
- Principles AS1–AS18, each with an operational corollary, covering: retrieved text and tool output as data rather than instructions; indirect injection as the dangerous form; why injection is not solved at the prompt layer; blast radius as a function of granted permission; task-scoped rather than agent-scoped authority; the separation of "who is asking" from "what I may do"; tool descriptions as attack surface; every writable channel as an exfiltration channel; agent output as untrusted input downstream; poisoned memory outliving its session; approvals that do not show the effect; the toolset as a supply chain; secrets in context as secrets disclosed; bounding capability rather than relying on choice; allowlists over blocklists; gates set by reversibility and reach rather than by confidence; audit logging as the precondition for investigation; and the safety floor as non-negotiable across reasoning profiles.
- Engineering rules ASE1–ASE95, grouped into provenance and the data/instruction boundary, indirect prompt injection, tool and resource integrity, data exfiltration, least privilege and excessive agency, identity and the confused deputy, memory integrity, output handling, human approval, agent and MCP supply chain, secrets in context, sandboxing and containment, and audit logging. Safety-floor rules are marked ★ and hold in every profile including Prototype.
- The provenance ladder — system / operator / user / untrusted, assigned by arrival channel and descending only — as the operational form of the pack's core claim, with the enforcement point at the actuator rather than the reader (`mental-models.md`, `decision-framework.md`).
- The exfiltration triangle as a named model: sensitive data, untrusted content, and a reachable egress path in one run: any two survivable, all three a live vulnerability, with the egress ingredient identified as the one teams routinely fail to classify.
- The control-versus-mitigation distinction as a review-grade test — every defense sorted by its enforcing component, with prompt hardening, delimiters, and injection classifiers recorded as mitigations that reduce frequency rather than as bounds — and a hard scoring cap of 49 for a design defended entirely by mitigations.
- The action-gate matrix keyed to reversibility and external visibility rather than to agent confidence, with the approval contract requiring a resolved artifact, frozen parameters, and no alternate ungated route to the same capability.
- Anti-patterns derived from the pack's own principles: the obedient document, the delimiter that was the whole defense, the helpful markdown image, the three ingredients nobody counted, the god-mode token, the agent that is everyone, the tool that changed its mind, the payload wearing a result, the rubber stamp, the back door around the gate, the sleeper fact, the rule that came from a document, the trusted echo, the secret in the system prompt, the sandbox with a network card, the blocklist of bad commands, the test suite that only types, the silent agent, and "it's only a prototype."
- Review checklist and scoring rubric that treat data leaving through a reachable channel, an irreversible or externally visible action taken without authority, and untrusted content executing or being written to durable memory as breaches rather than hardening gaps — with a hard cap at 59 for any open CRITICAL in every profile, 59 for an unsandboxed execution path, 69 for no tool-call audit log, 74 for no indirect-injection testing, 79 for over-broad credentials, and no credit for instance-only fixes.
- Standards cited: the OWASP Top 10 for Large Language Model Applications (LLM01 Prompt Injection cited with its number; sensitive information disclosure, supply chain, data and model poisoning, improper output handling, excessive agency, and system prompt leakage cited by category name, with current numbering left to the source), the OWASP Top 10 for Agentic Applications (tool and resource poisoning, memory poisoning, privilege escalation and identity confusion, human-approval bypass, agent supply-chain compromise — cited by name, item identifiers deliberately not reproduced), the NIST AI Risk Management Framework (the lifecycle frame behind the profile-adjusted rigor table and the audit requirements), and the Model Context Protocol specification (whose consent, data-exposure, tool-description-trust, and sampling-review expectations are restated as host-enforced rules in ASE72–ASE78).
- An injection threat-model worksheet, an egress enumeration audit, and an indirect-injection test generator as injectable prompt fragments, alongside the standard build-mode constraint block, security review lens, and tight-budget one-liner. The test generator explicitly rejects assertions on model refusal in favor of assertions on a named enforcing component.
- Scope boundary recorded: general web and API security remains `packs/security/owasp-top-10` and `packs/security/owasp-api-top-10`'s job and both load alongside this pack whenever the surface has an agent component; the shape of a tool is `packs/ai-engineering/tool-design` while this pack covers the controls guarding it; agent architecture and the written authority boundary are `packs/ai-engineering/agent-foundations`; context assembly as a quality discipline is `packs/ai-engineering/context-engineering`.
- Cross-links recorded to `core/constitution.md` (Article 2, the safety floor behind AS18), `core/authority-model.md` (the Level 1 assignment and its normative-requirement rule), `core/source-policy.md` (the standards clause requiring item identifiers be cited), `core/scoring-model.md` and `scoring/security-score.md` (the bands and the composite this pack feeds), and to the `security/owasp-top-10`, `security/owasp-api-top-10`, `security/nist-ssdf`, `ai-engineering/tool-design`, `ai-engineering/context-engineering`, and `ai-engineering/agent-foundations` packs — with individual rules naming the specific OW rule they extend (OW3, OW4, OW5, OW8, OW10, OW14, OW16, OW17).
