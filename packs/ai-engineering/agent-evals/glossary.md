# Glossary — Agent Evals Pack

- **Altitude** — the scope an eval case operates at: unit, tool-call, trajectory, or end-to-end. Each catches failures the others structurally cannot see, so a suite living entirely at one altitude has a blind spot with a name.
- **Baseline** — the recorded result a future change must beat, together with the version, corpus revision, grader version, and run count that produced it. A number alone is not a baseline, because it cannot establish whether a later comparison is even valid.
- **Calibration (of a grader)** — measuring a non-deterministic grader's agreement against human-labeled cases before its scores are trusted. Repeated whenever the grader model or the rubric changes; an uncalibrated judge produces measurements with an unknown error rate.
- **Contamination** — an eval measuring recall of an answer the system already had rather than the capability it claims to measure. Arrives by three routes: training data, the agent's accumulated context, and iteration against the suite itself.
- **End-to-end eval** — an eval grading whether the user's actual task was completed, judged by an external condition rather than by the agent's own account of it. The most expensive altitude and the only one that answers the question that matters.
- **Exact-match grader** — a grader comparing output to a reference by equality. Cheap and trustworthy on canonical forms (enums, IDs, numbers, structured fields), brittle in exactly the direction language varies, and therefore wrong for free prose.
- **Failure injection** — deliberately making a tool fail, time out, return malformed data, or deny permission inside an eval case, so recovery behavior is measured rather than assumed.
- **Flaky eval** — a case that passes and fails inconsistently on the same input at the same version. Its cost is not one case: it teaches readers to re-run rather than investigate, and re-running is applied uniformly to the genuine regressions in the same batch.
- **Golden dataset** — a fixed, representative, versioned set of inputs with known-good expected behavior. All three properties are load-bearing; a set missing one is a pile of examples that will eventually be mistaken for a golden dataset.
- **Groundedness** — whether each load-bearing claim in an output derives from the provided context or a tool result. A separate axis from correctness: an answer can be right but ungrounded, or grounded but wrong.
- **Hallucination rate** — the share of outputs containing a fabricated specific: an invented citation, a non-existent endpoint, a made-up figure. Reported as its own number, never folded into an accuracy score.
- **Held-out set** — a portion of the dataset never used for iteration or tuning, run and reported separately. Divergence between it and the iterated set is the primary detector for contamination by iteration.
- **LLM-as-judge** — a grader using a language model to score open-ended output against stated criteria. Flexible where no reference answer exists; carries its own biases (length, verbosity, self-preference) and requires calibration before its scores gate anything.
- **Negative case** — a realistic near-miss where the correct behavior is *not* to act, not to flag, or not to call the tool. The case class that catches false-positive drift, which no number of positive cases can.
- **Noise floor** — the run-to-run variance measured by putting the same version through the suite twice. Regression thresholds tighter than it fire constantly; claimed improvements smaller than it are not yet evidence of anything.
- **Pairwise comparison** — grading by asking which of two candidate outputs is better. Well matched to the question changes usually pose, weak for absolute quality (two poor outputs still produce a winner), and requiring order randomization to control position bias.
- **Position bias** — a judge's tendency to prefer whichever candidate was presented first, independent of quality. Measured by re-running a sample with the order swapped; unmeasured, it contaminates every pairwise number in the report.
- **Recovery rate** — the share of injected-failure cases after which the agent reaches the goal or escalates correctly. Graded across three outcomes — recovered, gave up, looped — because collapsing them to pass/fail hides which defect is present.
- **Regression threshold** — the numeric bar a run must clear, declared in a committed config before the change under test is run. A bar decided after seeing the result is a rationalization, not a threshold.
- **Rubric grader** — a grader enumerating named criteria with behavioral anchors, producing structured partial credit. Its value is that disagreement becomes locatable to a criterion; levels without anchors ("good / fair / poor") are not a rubric.
- **Task completion rate** — the share of end-to-end cases where the task was actually accomplished, verified externally. The outcome metric; step-level metrics sit beneath it as diagnostics and never substitute for it.
- **Tool-call eval** — an eval grading which tool was selected and with what arguments, including cases where the correct behavior is to call nothing.
- **Trajectory eval** — an eval grading the path an agent took rather than only its final output: step count, redundant calls, required steps in order, recovery from an error. Catches a correct answer reached by an unacceptable route.
- **Unit eval** — an eval grading one prompt and its response in isolation. The cheapest altitude; catches a broken instruction, and cannot see anything requiring more than one turn.
- **Vacuous pass** — a case that passes for the wrong reason: a grader matching anything, a path resolving to nothing, an assertion comparing a value to itself. Clusters in negative cases, where "nothing happened" is both the expected result and the signature of a broken check.
