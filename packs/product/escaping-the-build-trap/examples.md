# Examples — Escaping the Build Trap Pack

## Strategy-as-backlog vs. real strategy

Bad ("strategy"): "Q1: ship dark mode, SSO, mobile app. Q2: ship analytics dashboard, API v2."
Good: "Problem: enterprise prospects churn in trials because admin controls don't meet their security requirements. Guiding policy: prioritize enterprise-grade access control and auditability over net-new consumer features this half. Teams determine specific solutions via discovery."

## Cascade done right

Company vision: "Become the default tool for remote-first teams." → Product-line strategic intent: "Reduce time-to-first-value for new teams from 14 days to 3." → Team target condition: "Increase week-1 activation rate from 20% to 35%." → Team's own discovery determines the specific feature(s) — onboarding checklist, template library, guided setup — none dictated from above.

## Outcome-based roadmap (Now/Next/Later)

```
NOW: Reduce enterprise trial churn (in progress — access control discovery)
NEXT: Improve mobile activation (discovery starting)
LATER: Explore usage-based pricing (not yet scoped)
```

No committed dates on specific features; stakeholders see direction and sequencing without a broken promise risk.

## Declined request, documented

```
Request: "Add a built-in video calling feature" (from a large customer)
Decision: Declined for now
Reason: doesn't serve current strategic intent (enterprise access control);
  video calling is a crowded, non-differentiating capability; integrate
  with existing tools (Zoom/Meet) instead
Revisit: if ≥3 enterprise deals are blocked specifically on this in the
  next quarter
```

## Exec dashboard shift

Before: "Features shipped this quarter: 23. Story points: 340."
After: "Net revenue retention: 108% (+3pp QoQ). Trial-to-paid conversion: 18% (+2pp). Support ticket volume per active user: down 12%." Output metrics still tracked internally by teams, but not the headline the org optimizes toward.
