# Prompt Fragments — Escaping the Build Trap Pack

## Fragment: strategy/roadmap review lens

```text
Apply Escaping the Build Trap discipline (AKOS L3) to this strategy or
roadmap artifact:
- Does the strategy diagnose an actual problem and state a guiding
  policy, or is it a feature list with a strategic-sounding title?
- Does the roadmap use outcome/theme framing with rough horizons
  (Now/Next/Later), or does it commit specific features to specific
  dates beyond one planning cycle?
- Can each initiative be traced up to a company/product-line outcome via
  explicit reasoning, or does the chain terminate in an unexplained
  feature request at some layer?
- Is there evidence of features/requests explicitly declined for
  strategic reasons?
- Flag output-only success metrics (ship count, velocity) presented as
  the primary measure of success; recommend outcome/value metrics instead.
```

## Fragment: org-diagnosis lens

```text
Diagnose which layer of the organization shows build-trap symptoms:
team-level (feature-driven backlog, no discovery), strategy layer
(roadmap is a disguised backlog), executive-reporting layer (dashboards
reward output not outcomes), or org-design layer (PM role defined as
delivery coordination). Recommend fixing the highest layer showing the
symptom first — fixing team practice while executive incentives still
reward shipping volume won't hold.
```

## One-liner

```text
Build trap: measure value delivered, not output shipped; strategy is
problem + guiding policy, never a feature list; cascade intent not
specification through the org; say no often; outcome-based roadmaps
(Now/Next/Later), not date-committed feature lists.
```
