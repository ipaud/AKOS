# Decision Framework — Lean Startup Pack

## When Lean Startup applies fully

Genuine market/product uncertainty: new product, new segment, new business model, or a feature whose value to customers is genuinely unknown. Full hypothesis-testing discipline pays off.

## When to skip the ceremony

- Well-understood, low-risk changes (a proven feature pattern, a competitor-validated capability, a customer-requested fix with clear demand) don't need a formal leap-of-faith writeup — light validation (or none) is proportionate.
- Regulatory/compliance-mandated features have no hypothesis to test — build them correctly, skip the MVP framing.

## Choosing MVP type by what needs testing

| Risk to test | MVP type |
|---------------|----------|
| Will anyone want this at all? | Landing page / smoke test (measure signup/interest) |
| Will customers actually use it as designed? | Concierge (do it manually for a few customers) or Wizard-of-Oz (fake the automation) |
| Can we build and deliver it technically? | Feasibility spike, not customer-facing |
| Will they pay? | Real pricing page / pre-order, even before the product exists |

## Pivot types (choose the smallest that addresses the invalidated assumption)

Zoom-in (one feature becomes the whole product), zoom-out (the product becomes one feature of something bigger), customer-segment pivot (same product, different audience), channel pivot (same product, different distribution), value-capture pivot (different monetization). Choose based on *which specific assumption* failed — don't default to the most dramatic option.

## Balancing against Inspired-style discovery

Lean Startup and [Inspired](../inspired/decision-framework.md) overlap heavily (both validate before building); Lean Startup's vocabulary (MVP, pivot, innovation accounting) suits 0-to-1 product/company contexts, Inspired's vocabulary (four risks, empowered teams) suits established product organizations running many parallel initiatives. Use whichever vocabulary the team already speaks; don't force both simultaneously.
