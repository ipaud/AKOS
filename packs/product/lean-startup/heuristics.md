# Heuristics — Lean Startup Pack

- **Name the scariest assumption.** If the whole plan fell apart, which single assumption would have caused it? Test that one first, not the comfortable one.
- **The "what would we build to learn this in a week" test:** if the MVP concept takes longer than a couple of weeks to build, ask what smaller version could still generate the core learning.
- **Vanity metric smell:** any metric that trends up on a graph regardless of what the team does (cumulative totals, raw signups) is suspect — ask "what would make this go down, and would we notice?"
- **Cohort, not cumulative.** Compare cohorts (this month's signups' week-1 retention vs. last month's) instead of cumulative totals to see real trend changes.
- **The pivot checkpoint.** If 2-3 consecutive experiments fail to move the key metric despite genuine effort, that's the scheduled moment to ask pivot-or-persevere — not a reason to quietly run a fourth experiment hoping.
- **MVP scope-creep check:** if the "MVP" has grown to include features that don't test the riskiest assumption, cut them — they're scope, not learning.
- **Loop-speed audit:** how long does one full Build-Measure-Learn cycle currently take? If it's months, the fix is usually shrinking the Build step, not the Measure step.
