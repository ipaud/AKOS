# Principles — Lean Startup Pack

- **LS1 — Identify leap-of-faith assumptions before building anything.** Name the value hypothesis and growth hypothesis explicitly; test the riskiest one first.
- **LS2 — Enter the loop at Learn.** Decide what you need to know before deciding what to build; the build is sized to the learning goal, not the other way around.
- **LS3 — An MVP is defined by its learning payload, not its polish.** The right question is "what's the smallest thing that generates validated learning about the riskiest assumption?" not "what's a small version of the full product?"
- **LS4 — Prefer actionable metrics over vanity metrics.** A metric is actionable if a specific team action can be shown to move it, in a repeatable, causal way (cohort analysis, A/B testing) — not just correlated with time passing.
- **LS5 — Establish a real baseline before optimizing.** You can't know if an experiment moved the needle without a measured starting point using real (not projected) data.
- **LS6 — Schedule pivot-or-persevere decisions explicitly.** Don't let a failing hypothesis run indefinitely by never formally revisiting it; set a checkpoint in advance.
- **LS7 — A pivot is a hypothesis change, not a random direction change.** State which specific assumption was invalidated and what new assumption the pivot tests.
- **LS8 — Speed of iteration is a competitive advantage in its own right**, independent of any single experiment's outcome — optimize the cycle time of Build-Measure-Learn, not just each individual build.
