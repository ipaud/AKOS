# Prompt Fragments — Inspired Pack

## Fragment: product discovery lens

```text
Apply Inspired-style discovery discipline (AKOS L3) to this initiative:
- State the intended outcome (a metric expected to move, with a target),
  not just the feature to be built.
- Address all four risks explicitly: value (will customers want it),
  usability (can they use it), feasibility (can we build it), viability
  (does it work for the business).
- Recommend the cheapest prototype/experiment that resolves the riskiest
  open question before committing to a full build.
- Flag if engineers/design were absent from discovery before the solution
  was decided.
- Flag if this looks like a feature-factory request (pre-decided output,
  no stated outcome, no discovery) and suggest reframing as a problem
  statement.
```

## Fragment: review lens

```text
Review this product initiative/PRD against Inspired principles:
1. Outcome check — is there a stated metric + target, or only a feature
   description?
2. Four-risk check — value/usability/feasibility/viability each addressed?
3. Prototype check — was a low-fidelity validation done before build, or
   did this jump straight to production engineering?
4. Collaboration check — were engineers/design involved in discovery, or
   only handed a finished spec?
5. Kill-option check — could this discovery have concluded "don't build
   it," or was the outcome predetermined?
```

## One-liner

```text
Inspired: give teams problems/outcomes not features; validate value,
usability, feasibility, and viability before building; prototype cheap
and fast; product+design+engineering collaborate in discovery, not a
handoff relay; measure outcomes post-launch, not just ship count.
```
