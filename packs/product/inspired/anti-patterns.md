# Anti-Patterns — Inspired Pack

## Feature factory

Team backlog is a prioritized list of pre-decided features with dates; success is measured by ship count; no stated outcomes; discovery, if it exists, only validates feasibility. Fix: IN1, IN6 — problems and outcomes replace the feature list.

## Discovery theater

A "discovery phase" exists on paper but always concludes "yes, build it" — no idea has ever been killed. Value risk is never actually tested, just asserted by whoever proposed the feature. Fix: heuristic kill-rate check; genuinely test value risk with real customers.

## Engineering as spec-execution

Engineers see the idea for the first time at spec handoff, after product and design have already committed to a solution; feasibility problems surface mid-build, causing rework or scope cuts under deadline pressure. Fix: IE4 — engineers in discovery from the start.

## Production-grade prototypes

Spending 6 weeks building a fully-engineered version to "test" an idea that a clickable mockup could have tested in 3 days. Confuses prototype fidelity with production readiness, burning the build budget before the value question is even answered. Fix: IN4, prototype-fidelity decision framework.

## Roadmap-as-strategy

A 12-month roadmap of named features presented as "the strategy," reviewed and re-committed to quarterly regardless of what discovery learns in the interim — treating a list of outputs as if it were a set of validated bets. Fix: mental model distinction — vision/strategy/roadmap are different things; roadmaps should follow discovery, not precede it.

## Metric-free launches

A feature ships and nobody checks whether the intended outcome moved — success is silently assumed because it shipped on time. Fix: IE5 — outcome measured and reported post-launch, every time.
