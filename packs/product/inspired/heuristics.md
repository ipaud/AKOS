# Heuristics — Inspired Pack

- **Feature-team smell test:** if the team's backlog is a list of pre-specified features with delivery dates and no stated customer problem or success metric, it's a feature team regardless of what it's called.
- **The four-risk audit:** for any initiative, can you state in one sentence each how value, usability, feasibility, and viability were checked? Any blank = unmanaged risk.
- **Cheapest-experiment-first:** before scoping an engineering build, ask "what's the cheapest thing we could do this week to learn if this is worth building?" — usually a prototype, a concierge test, or a landing page, not a spike.
- **Outcome-statement test:** can the initiative's success be stated as a number that moves ("reduce onboarding drop-off from 40% to 25%") rather than a delivery checkbox ("ship onboarding redesign")? If not, define the outcome before starting.
- **Engineer-in-discovery check:** were engineers involved before the solution was decided, or only after, to "estimate" a spec handed to them? The latter forfeits feasibility risk-reduction and morale.
- **Kill-rate check:** does discovery ever produce a "don't build this" conclusion, or does everything that enters discovery eventually ship? A 0% kill rate usually means discovery isn't actually happening.
