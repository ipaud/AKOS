# Decision Framework — Continuous Discovery Habits Pack

## Which opportunity to pursue first (tree branch selection)

Score opportunities by: (a) how many independent interviews surfaced it (pattern strength), (b) proximity to the owned outcome (does solving it plausibly move the metric), (c) current pain intensity (workaround cost customers already pay). Pursue the highest-scoring opportunity's solutions first; keep others visible on the tree for later, not discarded.

## Which solution to pursue first (within an opportunity)

Prefer the solution with the fewest, cheapest-to-test unevidenced assumptions over the most impressive-sounding one — cost-to-validate is a legitimate prioritization input, not just impact.

## Assumption test design

1. List assumptions (CE4).
2. Plot importance × evidence; pick the top-right quadrant (important, unevidenced) item.
3. Choose the cheapest test that produces real evidence: a story-based interview probe, a concierge test, a fake-door/landing-page test, a feasibility spike ([Inspired's prototype-fidelity framework](../inspired/decision-framework.md) applies directly here).
4. Record the result on the tree next to the solution node; update the assumption map.

## When to break the weekly cadence

Genuine one-off circumstances (team on-call incident, planned leave) justify skipping a single week — but a skipped week is logged and the next week's touch isn't optional. Repeated skipping is a signal the habit needs organizational protection (a fixed calendar slot, explicit manager support), not that the habit itself is wrong for this team.

## Team size / solo-founder adaptation

Continuous interviewing scales down: a solo founder or 2-person team can run the same weekly-touch habit informally (a coffee chat, a support-ticket deep dive) without formal recruiting infrastructure — the discipline (weekly, story-based, synthesized onto a tree) matters more than the ceremony.
