# Review Checklist — Privacy Pack

Binary checks. Each cites the engineering rule it enforces. Critical items block in every
reasoning profile the moment the system holds one real person's data.

## Critical (blocks in every profile)

- [ ] Every personal-data field is in an inventory with purpose, lawful basis, retention,
      and destinations. (PR1)
- [ ] New personal-data fields are justified at review, not added speculatively. (PR2)
- [ ] Each processing purpose names a lawful basis chosen before implementation. (PR6)
- [ ] Consent records store scope, wording version, timestamp, and method — not a
      boolean. (PR7)
- [ ] Consent is unticked by default, granular, and reject is as easy as accept. (PR8)
- [ ] Withdrawal actually stops the processing, downstream included. (PR9)
- [ ] Data not required by a stated purpose is absent from the schema. (PR13)
- [ ] Analytics and telemetry are pseudonymous unless a purpose requires the join. (PR14)
- [ ] Logs and error reports carry no credentials, tokens, or personal data beyond a
      pseudonymous identifier. (PR15)
- [ ] The privacy-preserving option is the shipped default. (PR16)
- [ ] Every personal-data category has a retention period enforced by a mechanism. (PR20)
- [ ] Account deletion covers every destination listed in the inventory. (PR21)
- [ ] Backup retention is bounded, and re-applying a deletion after restore is
      documented. (PR22)
- [ ] Access and portability are generated by code in a machine-readable format. (PR26)
- [ ] Erasure, rectification, and objection have implemented paths with identity
      verification. (PR27)
- [ ] Every processor is listed with what it receives, why, and where — AI/LLM APIs
      included. (PR31)
- [ ] No personal data reaches a service that skipped processor review. (PR32)
- [ ] A breach runbook exists before launch. (PR36)
- [ ] Detection exists for the events a breach would produce. (PR37)
- [ ] The privacy notice matches the inventory. (PR40)
- [ ] Supabase: RLS is enabled on every table holding personal data. (PR44)
- [ ] Supabase: the project region was chosen deliberately. (PR45)

## High

- [ ] Indirect identifiers (IP, device, session, advertising IDs) are in the
      inventory. (PR3)
- [ ] Non-essential cookies and storage are not set before consent. (PR10)
- [ ] Analytics and session recording load only after consent. (PR11)
- [ ] Marketing consent is separate from transactional messaging. (PR12)
- [ ] Non-production environments use synthetic or anonymized data. (PR18)
- [ ] Logs and analytics have their own enforced retention windows. (PR23)
- [ ] Soft-deleted records are hard-deleted or anonymized on a schedule. (PR24)
- [ ] Third-party stores are covered by the deletion path or listed as a gap with an
      owner. (PR25)
- [ ] High-risk processing has a written assessment made before the build. (PR38)
- [ ] Supabase: deletion covers child tables, storage objects, and auth records. (PR46)
- [ ] Supabase: a test asserts data past its retention window is gone. (PR47)

## Medium

- [ ] Special-category data is flagged, or its absence asserted. (PR4)
- [ ] Free-text fields likely to attract personal data are treated as personal
      data. (PR5)
- [ ] Precision is no higher than the purpose needs. (PR17)
- [ ] Admin/support views are role-limited and access is logged. (PR19)
- [ ] Subject-rights requests are logged with timestamps. (PR28)
- [ ] Automated decisions with significant effect have a human-review path. (PR30)
- [ ] Data sent to each processor is the minimum it needs. (PR35)
- [ ] The risk assessment names the risk to the person. (PR39)
- [ ] Surprising collection is surfaced in context, not only in the notice. (PR41)
- [ ] Consent UI is keyboard-operable and meaningfully labeled. (PR42)
- [ ] Supabase/Postgres: personal-data access is granted per role, column-limited where
      applicable. (PR48)

## Low

- [ ] Refusals or partial fulfilments of a request are recorded and communicated. (PR29)
- [ ] Vendor sub-processor changes are monitored. (PR34)
- [ ] Hosting region is set in infrastructure configuration. (PR33)
- [ ] Privacy-choice copy states the consequence of each option. (PR43)
- [ ] Point-in-time recovery window is set consciously. (PR49)

## Process

- [ ] The inventory is re-verified against the schema at each release, not written
      once. (PR1, PR40)
- [ ] A privacy review happens before a new processor or SDK ships, not after. (PR32)
