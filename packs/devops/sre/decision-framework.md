# Decision Framework — SRE Pack

SRE rigor by profile: Prototype/Internal Tool — basic uptime monitoring, no formal SLOs needed; MVP — SLOs on the 1-2 most critical journeys, symptom-based alerting; Production — full SLI/SLO/error-budget practice, runbooks, blameless postmortems; Enterprise — the above plus formal on-call rotations, SLA commitments to customers, chaos engineering/game-day exercises. Setting SLO targets: start from what users actually need (not "as high as possible") — 99.9% for most consumer apps is meaningfully different effort from 99.99%, and the marginal reliability often isn't worth the engineering cost below Enterprise-tier stakes. When error budget is exhausted: pause non-critical feature launches, prioritize the reliability work identified in recent postmortems, communicate the tradeoff to stakeholders using the budget framing (not an ad hoc "no" that reads as arbitrary).
