# Decision Framework — Git Pack

Merge vs squash vs rebase: squash-merge for feature branches with messy intermediate commits (clean main history, one commit per feature); merge commit when preserving the full development history has real value (rare); rebase for keeping a personal feature branch current with main before review. Branching strategy: trunk-based (short-lived branches, frequent merges to main) for teams with strong CI/CD and feature flags; Git Flow (develop/release/hotfix branches) for teams with scheduled release trains — trunk-based is the simpler default absent a specific reason for Git Flow's extra ceremony. Secret exposure response: rotate the secret first (assume it's compromised the moment it's pushed, even to a private repo), then clean history (`git filter-repo`/BFG) as a secondary cleanup, never the primary fix.
