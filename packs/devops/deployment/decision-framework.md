# Decision Framework — Deployment Pack

Rollout strategy choice: trivial/low-risk change (copy, minor config) → direct deploy fine; moderate-risk (new feature, behavior change) → canary (5-10% traffic, monitor, ramp) or rolling; high-risk (infra/schema change, major rewrite) → blue-green with explicit cutover decision point. Migration sequencing: additive changes (new column, new table) → deploy anytime, safe. Changes requiring both old and new code paths during transition → expand-contract across 2+ deploys. Purely destructive changes (drop column/table) → only after confirming zero remaining reads, typically weeks after the corresponding application change ships. Deploy timing: high-risk deploys scheduled when the team can actively monitor (not Friday evening, not right before a holiday) unless the team has genuine 24/7 on-call coverage.
