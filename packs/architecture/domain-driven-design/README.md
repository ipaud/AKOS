# Pack: Domain-Driven Design

**Domain:** Architecture · **Authority:** Level 3 (methodology) · **Version:** 1.0.0

Operationalizes DDD's core value: modeling software around the business domain's real language and boundaries — ubiquitous language, bounded contexts, aggregates, entities vs value objects — with explicit guidance that full tactical DDD is usually overkill below a certain complexity threshold.

Independent distillation; not affiliated with or endorsed by the source author. See [references.md](references.md).

## When to load

- Modeling a complex business domain with real invariants and rules.
- Deciding service/module boundaries in a system with multiple subdomains.
- Diagnosing "everyone means something different by 'customer'" naming chaos.
- Evaluating whether microservice boundaries make sense (bounded contexts often should precede them).
