# Glossary — Refactoring Pack

- **Refactoring** — restructuring code without changing observable behavior.
- **Code smell** — a surface symptom indicating an underlying design problem.
- **Rule of three** — duplicate twice freely; abstract on the third occurrence.
- **Two hats** — the discipline of never mixing "adding function" and "refactoring" in one step.
- **Characterization test** — a test capturing current (possibly imperfect) behavior before refactoring, as a safety net.
- **Extract Function / Move Function / Inline / Rename / Introduce Parameter Object** — named catalog refactorings.
- **Strangler fig pattern** — incrementally replacing a legacy system behind a routing facade instead of a big-bang rewrite.
- **Technical debt** — the accumulated cost of deferred refactoring, paid with interest in future change difficulty.
