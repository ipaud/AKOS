# Decision Framework — GraphQL Pack

REST vs GraphQL: many clients with divergent, evolving data needs (mobile + web + partners) → GraphQL's flexibility pays off. Simple, stable, small API surface → REST is simpler to build, cache (HTTP caching works naturally), and secure. Query complexity limiting approach: max-depth limiting is simplest and catches most abuse cheaply; cost-based limiting (assigning weights per field/connection) is more precise but more work — start with depth limiting, add cost-based limiting if depth alone proves insufficient. Schema-first vs code-first: schema-first (SDL as source of truth) aids cross-team contract clarity; code-first (resolvers generate schema) aids type-safety in strongly-typed backends — either is fine, consistency within the codebase matters more than the choice.
